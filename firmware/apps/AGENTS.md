# Local robot-app experiment
- Build this overlay from its immutable v61 commit using prepare_apps.py; never compile the withdrawn checkout as an app release. Why: a version label alone does not restore the working voice baseline.
- Keep apps declarative and bounded, use ScreenImage's existing canvas and the shared authenticated route table, and yield to all established hardware owners. Why: app modes must not add competing audio, display or network paths.
- Keep v61 as the stable restore target; new app firmware is experimental until tested on the physical robot. Why: a host build cannot prove microphone or wake stability.- Each app persists only its last accepted configuration in its own small LittleFS file (`/apps.json` clock, `/focus.json` focus timer) through injected store hooks; boot loads without auto-starting; starting one app stops the other. Offline clock starts use the robot clock and the forecast's original wall-clock TTL. Why: apps must work without Hub/network while a reboot never seizes the screen, two apps never fight for the panel, and stale weather is never presented as current.
- Timers (focus app) yield the screen to voice/menu/camera but keep counting; touch/wake leave fullscreen to the widget instead of stopping. No speaker cues from apps. Why: the speaker/mic are owned by voice and half-duplex.
- On-robot menu pages are paged by pure tested `MenuPagerPolicy.h`; only the main menu acts on release, all other menu screens keep press-edge taps. Why: swipes must not trigger buttons, and the proven Wi-Fi keyboard must not change.
- Session end never sets the sleep face before the farewell drains; one-shot app tools ask Gemini to also call end_session. Why: the face flashed asleep before speaking.
- Voice app control goes through one core Gemini tool per app (e.g. `control_timer` → `FocusApp::voice`) patched into GeminiToolBridge by prepare_apps.py; voice starts are widget-only and never overwrite saved app settings. Why: fullscreen would be immediately displaced by the active conversation, and a spoken one-off must not change the user's configured routine.
- The Tuya worker counts as busy until its task exits, not just until cancelled; Tuya, Tavily and Commons block wake listening. Check the 8 KiB DMA guard only before listening starts, never to stop an active listener. Why: v74 exhausted I2S memory; v75's continuous guard oscillated on the listener's own allocations during settings saves.
