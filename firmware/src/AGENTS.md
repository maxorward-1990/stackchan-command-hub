# Performance measurement rules
- WakeNet9 retains PSRAM detection mode; tune its real threshold and gate candidates on bounded completed-PCM peak evidence through Personality, never a single tail chunk or unsafe model reset. Why: SDK flash mode is WakeNet10-only and peak alone cannot prove silence.
- The explicit v64 active-dialogue reset archives the current raw file once with a retry-safe marker before compaction; never delete facts, private memory, settings or earlier archives. Why: unverified transcript contamination must be reversible.
- Optional proximity control uses tested ProximityPolicy and one Proximity I2C owner on the main loop, sharing touch voice actions with no menu actions; require clear-space rearming, reject saturation/read failures and pause for conflicting inputs. Why: hand control must not allocate, touch audio/network ownership or repeatedly stall on a failed sensor.
- Current-time questions use a fresh local get_current_time tool with tested ClockPolicy UTC/timezone conversion and clock-validity reporting; setup time is labelled stale context, never a live clock. Why: indexed search snippets and long-lived setup timestamps give incorrect times.
- The shared authenticated /api/performance route controls the existing bounded PerfMonitor; it allocates no persistent capture buffer. Why: one-click host test capture must use the same control path for all transports.
- Keep CPU sampling in constant-time FreeRTOS tick hooks with no I/O or allocation; report it as an estimate, not runtime accounting. Why: ISR work and tick aliasing are not measured exactly.
- Emit bounded schema-v1 `[PERF]` telemetry at most once per second and skip rather than wait for UART space; export no secrets or conversation content. Why: instrumentation must not stall Live playback or expose private data.
- Keep initial audio prefill separate from starvation recovery in tested pure policies, and measure scoped elapsed maxima including nested calls without summing overlapping stages. Why: small network gaps must not retrigger full startup buffering or create misleading bottleneck claims.- Gemini Live WebSocket/TLS runs only in the core-0 `gemini_ws` task; it copies frames into a bounded queue and sends queued outgoing text, while robot state, speaker, LCD and Serial are handled on the main loop (bounds in tested `WsTransportPolicy.h`). Why: blocking TLS reads froze the face and starved the speaker on hotspots.
- Battery, motion and RTC rules live in pure tested `SensorPolicy.h`; `SensorMonitor` polls them on the main loop at 50 Hz with own servo/speaker motion suppressed, and only wakes/changes the face (never starts a conversation). Why: shared I2C bus must stay short and self-vibration must not fake knocks.
- Smart Life lights: Tuya cloud (EU) via pure tested `SmartHomePolicy.h` + one 10KiB `SmartHome` worker (TLS buffers live on heap; stack must stay small so Live+Tuya TLS fit together); keys only in LittleFS secrets; `control_lights` declared only when enabled+configured; HTTP/USB use `/api/home` POST-start/GET-poll. Why: no home server, one shared path. Scenes are owner-defined local device-step lists in `/home_scenes.json` (validated by the policy, edited via `/api/home/scenes`), run as plain device commands. Why: Tuya cloud scenes are a paid API.
- Owner personality (sleep/screen timing, brightness, per-state LED and eye colours, face detail flags, subtitles, listen cue, touch-menu, nod) lives in pure tested `PersonalityPolicy.h`, persisted by `Personality` in `/personality.json` and edited via `/api/personality`, applied live without reboot; Command Hub previews it with a browser replica of the face and two top LED bars. Why: personality tweaks must not require reflashing, and streaming LCD pixels would starve Live audio.
- Tavily preparation releases WakeNet/Live before worker reservation on every entry; voice results cross a fresh Live connection as bounded untrusted clientContent, never old tool IDs, with cancellation gates in SearchHandoffPolicy. Why: TLS owners must not compete for internal RAM or replay stale turns; retain certificate verification.
- mbedTLS allocates through `TlsAllocator` (installed first in setup): large blocks PSRAM-first, small internal-first, policy in tested `TlsAllocPolicy.h`. Why: the prebuilt core forces TLS into internal RAM, where fragmentation after WakeNet/search broke every later handshake.
- Model-supplied gesture names go through pure tested `GestureAliasPolicy.h` before the servo queue; unknown names become a gentle real gesture. The touch menu opens only on an idle upward swipe (`TouchMenuPolicy`). Why: tool errors cost a model turn, and accidental holds paused the wake word.

- Manual voice completion retains startup/quiet taps, drains captured PCM, then uses paced bounded silence and the valid automatic-VAD audioStreamEnd; cancel pending completion on stop or server response. Why: volume gates swallowed taps and burst/unfinished audio can leave no-reply turns.
- Explicit stop returns the head to absolute neutral and gates WakeNet during servo motion; idle memory guards use tested IdleMemoryPolicy, bounded cooldown and measured WakeNet release only, never reboot/flash writes or claimed compaction. Why: privacy stops must settle safely and low largest-block readings alone do not prove leaks.
