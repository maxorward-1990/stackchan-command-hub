# Robot configuration and diagnostics
- Unified test capture uses the existing USB line/command subscriptions and shared robot client; starts acknowledged telemetry, captures bounded browser-memory events with UTC reception/elapsed times, restores the previous telemetry state and exports only explicit test-period text plus allowlisted status. Why: one-click correlation must not add robot buffers, capture PCM, fetch historical/private memories or upload automatically.
- Keep Wi-Fi validation and secret-safe log summaries in the pure tested network policy; send configuration only through the shared robot client, checking secret-write success before reboot. Why: all transports need identical behavior without leaking credentials.
- Stereo diagnostics are explicit finite runs of the shared sensor API, exporting measurements only, never PCM or automatic capture. Why: mic/speaker hardware is half-duplex and diagnostic data must remain local.- Microphone health verdicts (dead channel, duplicated mono, side response) come from pure tested `micVerdict`/`channelFindings` in robot-network.ts; USB serial query strings are parsed by tested `firmware/src/SerialQueryPolicy.h`. Why: USB and HTTP must answer identically and hardware faults must be judged from evidence.
